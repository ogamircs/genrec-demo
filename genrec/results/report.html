GenRec on Yelp

An LLM fine-tuned to generate the name of the next restaurant a user will visit, benchmarked against ten other recommenders on the same leave-one-out test — then scaled up (3B, all 98k training windows, catalog-constrained 20-beam decoding) to see how far it could climb. The upgrades bought +56% HR@10; ranking-optimized CF still tops the table — ahead of both deep-CTR baselines, which tie each other.

What GenRec actually does

The paper's recipe: item names, not IDs — one instruction-formatted example per position in each user's visit sequence

SystemYou are a restaurant recommendation system.
UserGiven a list of restaurants the user has visited in chronological order, predict the restaurant the user will visit next.

Restaurants visited: Four Peaks Brewing Co, Heart Attack Grill, Gold Bar Espresso, Tokyo House, Scottsdale Fashion Square, Rula Bula, C-Fu Gourmet Restaurant, Salt River Tubing and Recreation, Pei Wei Asian Diner, Rocky Mountain Chocolate Factory, Taqueria Mexico…
Assistant — the only tokens the loss seesJoe's Real BBQ

Two recipes were run. v1 (quick): Llama-3.2-1B, 30,000 windows (≤15 prior visits each), 2 epochs, free 10-beam search. v2 (scaled): Llama-3.2-3B, all 98,278 windows, 3 epochs (4.3 h), and catalog-constrained 20-beam search — a token trie over the 7,218 business names forces every beam to spell a real restaurant. Both: LoRA r=16, lr 3×10−4, loss on the target name only. The recommendation is literally generated text, never a lookup.

Training scale bought +26% HR@10; constrained 20-beam decoding another +24% (and 100% in-catalog, 1,958/1,988 full lists vs v1's 8.9-name average). Excluding already-visited names from the trie changed nothing — the model wasn't wasting beams on revisits. The cost: top-5 slipped ~15%, from the full-data training itself (popularity-skewed windows blunt the sharp personalized guesses), not from decoding. Cold-start ceiling for every model: 2.8% of targets never appear in training.

Methodologies tested

Eleven recommenders, one shared protocol: train on everything before each user's last visit, predict that visit

GenRec LLM · generative Ji et al., arXiv 2307.00457. 4-bit QLoRA via unsloth (r=16, α=32, all attention+MLP projections); sequences of business names → next name, loss on the target only, lr 3e-4. v1: Llama-3.2-1B, 30k examples, 2 epochs, free 10-beam (21 min). v2: Llama-3.2-3B, 98k examples, 3 epochs (4.3 h), catalog-trie-constrained 20-beam.
Popularity non-personalized Items ranked by training rating count; the same list for everyone minus each user's seen items. The strongest classic baseline here — and the honest bar any personalized model must clear.
Rank-based classic baseline Items ranked by average rating among those with ≥50 training interactions (412 qualify). Better than the CF models at top-N, worse than raw popularity.
User-user KNN classic baseline surprise's KNNBasic formula implemented in numpy: cosine similarity over co-rated items, k=40 neighbors, min_k=6 (tuned values). Predicts ratings well (RMSE 0.99) but its top-10 lists are dominated by obscure items a handful of neighbors loved.
Item-item KNN classic baseline Same structure, item side: msd similarity, k=30, min_k=9 (tuned values). Numpy implementation validated to 1×10−6 against an independent per-pair implementation.
FunkSVD classic baseline Biased matrix factorization (μ + bu + bi + qi·pu), 100 factors, SGD with tuned n_epochs=20, lr=0.01, reg=0.2. Best rating predictor of the three (RMSE 0.93) — and still near the bottom at next-item retrieval.
SAR recommenders lib Smart Adaptive Recommendations from recommenders.models.sar: Jaccard item co-occurrence similarity × time-decayed user affinity (30-day decay on review timestamps), recommend_k_items with seen-item removal. Fits in 3 s.
BPR recommenders lib Bayesian Personalized Ranking (Rendle et al. 2009) via Cornac, the backend the recommenders library wraps: implicit-feedback MF with a pairwise ranking loss — k=100, 200 iters, lr 0.01, reg 0.001, seed 42. Best model in the table on every metric.
DeepFM deep CTR Guo et al., arXiv 1703.04247, in PyTorch: an FM component (order-1 + all pairwise interactions) and a 128→64 MLP sharing one embedding table over 6 categorical fields — user/item ids plus log-bucketed activity, popularity and average-rating fields. Implicit feedback, 8 uniform negatives per positive, binary cross-entropy. Dim/negatives/dropout chosen by an 18-config grid on a validation split (each user's last training visit); it picked dim 16, 16 negatives, no dropout. Second overall — ~1 min to train.
Wide & Deep deep CTR Cheng et al., arXiv 1606.07792 — the architecture DeepFM was written to improve on. A linear wide model over the raw fields plus four hand-built cross-products (user×item-popularity, user×item-rating, activity×popularity, rating×rating) for memorization, jointly trained with a separately-embedded MLP for generalization. Same fields, negatives, loss and grid as DeepFM. Ties DeepFM — the FM component buys nothing at 6 fields.
PinSage graph GCN Ying et al., arXiv 1806.01973 — the GCN deployed at Pinterest, here over the bipartite user/business graph. Neighbourhoods are the top-50 businesses by L1-normalized visit count of random walks with restart (Personalized PageRank in the limit), aggregated by importance pooling (a weighted mean over those counts); two convolutional layers, then the paper's G2·ReLU(G1h+g) head. Max-margin ranking loss, 500 negatives shared per minibatch, plus curriculum hard negatives from a PPR rank band. The only model here with no item-ID parameters — a business is its content features plus its graph position. Mid-table on accuracy, first on coverage.

Why numpy and not scikit-surprise: surprise ships source-only and this machine has no C compiler. The implementations were validated under a classic rating-prediction protocol (≥100-review cohort, random 80/20 rating split) before use:

CoClustering was skipped — the most complex to implement, and its performance tracks SVD's.

What the numbers say

Ranking-optimized CF wins overall. BPR tops every metric even after GenRec's upgrades. Models trained to rank beat models trained to predict ratings by an order of magnitude at top-N, and on this sparse, weakly-sequential data they beat the LLM too.

Deep learning did not beat the objective. DeepFM and Wide & Deep — both with MLPs, six feature fields and identical grid searches — finish second and third, comfortably ahead of SAR (75 and 74 mean hits vs 62) and popularity, and ~18% behind plain BPR (91 mean hits). BPR has no neural network at all; what it has is a pairwise ranking loss, while both deep models optimize pointwise classification over sampled negatives. Architecture lost to objective.

PinSage reproduces four of its five ablation rungs — but not the headline. Running the paper's own Table 1 ladder on this data (3 seeds each, test HR@10): mean-pooling-xent 0.0148 (worst, as published), max-pooling 0.0221, mean-pooling 0.0258, mean-pooling-hard 0.0262 — the published order. Importance pooling, the paper's 46% → 67% jump, gives 0.0260: nothing. The rest of the sweep says why. Across an 18-config grid at 3 seeds, only the margin δ clears the noise floor (0.1 > 0.3 > 0.5 in all six dim × T cells); T, embedding size, the hard-negative band and even random-walk fidelity (55% → 83% agreement with exact Personalized PageRank) all land inside run-to-run variance. Weighting a neighbourhood pays when it is a 50-item sample of three billion — a 2-hop expansion of a 10,165-item catalog already reaches ~9,700 of them, so there is nothing left to weight.

Accuracy is not the only axis. PinSage recommends 1,934 distinct businesses across the 1,988 lists, against BPR's 784, DeepFM's 678 and popularity's 31; its most-recommended item appears in 13.8% of lists against BPR's 38.1% and popularity's 88.6%. With no ID parameters it can only rank by content and graph position, and its neighbour structure holds up on inspection (Pizzeria Bianco → La Grande Orange Pizzeria, Cibo, True Food Kitchen). That is precisely the profile that loses an HR@10 contest whose hits concentrate in popular restaurants — and the least popularity-biased catalogue coverage in the benchmark.

The two deep architectures are indistinguishable. DeepFM's selling point over Wide & Deep is replacing hand-built cross features with an FM term that learns every pairwise interaction automatically. Here that is worth one hit out of 1,988. With only six fields — two of them carrying the real signal — four hand-picked crosses cover the same ground; DeepFM's edge needs the wide, messy feature space this dataset does not have. The one hyperparameter that mattered for either model was the negative count (16 > 8 > 4 at every embedding dim); capacity did nothing consistent.

The GenRec upgrades worked — up to a ceiling. Scaling to 3B/full data and constraining beams to the catalog lifted HR@10 by 56% (0.0171 → 0.0267) and pushed NDCG@10 past popularity, at the cost of ~15% at top-5 (full-data training skews toward popular names). GenRec v2 sits clearly above every rating-prediction baseline, within 4% of popularity at HR@10 — and still well short of BPR (0.0428).

Rating predictors are poor top-N retrievers. KNN and SVD predict ratings well (RMSE 0.93–0.99) yet almost never surface the next-visited restaurant. Optimizing squared error rewards obscure items with a few perfect ratings.

The LLM internalized the catalog. 97.7% of freely generated names are real businesses, and the hit/miss examples show it exploiting name semantics — yogurt shops for yogurt fans, sushi for sushi regulars — exactly the paper's motivation for names over IDs.

Consistent with the paper. GenRec reported HR@10 = 0.025 on sparse Amazon Toys — where it also lost to its baseline — versus 0.131 on dense MovieLens, where it won. This Yelp result sits squarely in the sparse-data pattern.

Caveats

  • One training run per recipe, no hyperparameter search — except the two neural CTR models, whose grid search on a validation split gives them an advantage the other baselines did not get.
  • Absolute hit counts are small (55–97 of 1,988 users), so gaps under ~10 hits sit inside the noise; use the seed-stability table rather than the single-run ordering.
  • Name-level evaluation merges chain locations (every “Subway” counts as one item) — applied equally to all models.
  • Paths not yet tried: hybrid BPR-candidates + LLM reranking, richer prompts (ratings, categories, city), and 7B-class models per the paper.

python genrec/01_prepare_data.py       # split + 98k training examples
python genrec/02_classic_baselines.py  # classic baselines + sanity check
python genrec/03_genrec_train.py       # v2: 3B, 3 epochs, ~4.3 h on RTX 5070 Ti
python genrec/04_genrec_infer.py       # constrained 20-beam generation, ~22 min
python genrec/06_recommenders_baselines.py  # SAR + BPR (py3.11 venv, see README)
python genrec/07_neural_ctr_baselines.py  # DeepFM + Wide & Deep (--sweep re-runs the grid)
python genrec/08_pinsage.py               # PinSage (--sweep main|band, --variant ablations)
python genrec/05_evaluate.py           # final table (all variants)
