What GenRec actually does

The paper's recipe: item names, not IDs — one instruction-formatted example per position in each user's visit sequence

SystemYou are a restaurant recommendation system.
UserGiven a list of restaurants the user has visited in chronological order, predict the restaurant the user will visit next.

Restaurants visited: Four Peaks Brewing Co, Heart Attack Grill, Gold Bar Espresso, Tokyo House, Scottsdale Fashion Square, Rula Bula, C-Fu Gourmet Restaurant, Salt River Tubing and Recreation, Pei Wei Asian Diner, Rocky Mountain Chocolate Factory, Taqueria Mexico…
Assistant — the only tokens the loss seesJoe's Real BBQ

Training: 30,000 such windows (≤15 prior visits each) sampled from the 98,278 possible positions in the 1,988 training sequences, LoRA rank 16 (11.3M trainable parameters, 0.9% of the model), lr 3×10−4, 2 epochs. At test time the model runs 10-beam search and the deduped beams become the top-10 list — the recommendation is literally generated text, never a lookup.

Methodologies tested

Eight recommenders, one shared protocol: train on everything before each user's last visit, predict that visit

GenRec LLM · generative Ji et al., arXiv 2307.00457. Llama-3.2-1B-Instruct, 4-bit QLoRA via unsloth (r=16, α=32, all attention+MLP projections). Sequences of business names → next name; loss on the target only; lr 3e-4, 2 epochs, effective batch 16. Inference: 10-beam search, deduped. Trains in 21 min, infers in 3.8 min.
Popularity non-personalized Items ranked by training rating count; the same list for everyone minus each user's seen items. The strongest classic baseline here — and the honest bar any personalized model must clear.
Rank-based classic baseline Items ranked by average rating among those with ≥50 training interactions (412 qualify). Better than the CF models at top-N, worse than raw popularity.
User-user KNN classic baseline surprise's KNNBasic formula implemented in numpy: cosine similarity over co-rated items, k=40 neighbors, min_k=6 (tuned values). Predicts ratings well (RMSE 0.99) but its top-10 lists are dominated by obscure items a handful of neighbors loved.
Item-item KNN classic baseline Same structure, item side: msd similarity, k=30, min_k=9 (tuned values). Numpy implementation validated to 1×10−6 against an independent per-pair implementation.
FunkSVD classic baseline Biased matrix factorization (μ + bu + bi + qi·pu), 100 factors, SGD with tuned n_epochs=20, lr=0.01, reg=0.2. Best rating predictor of the three (RMSE 0.93) — and still near the bottom at next-item retrieval.
SAR recommenders lib Smart Adaptive Recommendations from recommenders.models.sar: Jaccard item co-occurrence similarity × time-decayed user affinity (30-day decay on review timestamps), recommend_k_items with seen-item removal. Fits in 3 s.
BPR recommenders lib Bayesian Personalized Ranking (Rendle et al. 2009) via Cornac, the backend the recommenders library wraps: implicit-feedback MF with a pairwise ranking loss — k=100, 200 iters, lr 0.01, reg 0.001, seed 42. Best model in the table on every metric.

Why numpy and not scikit-surprise: surprise ships source-only and this machine has no C compiler. The implementations were validated under a classic rating-prediction protocol (≥100-review cohort, random 80/20 rating split) before use:

CoClustering was skipped — the most complex to implement, and its performance tracks SVD's.

What the numbers say

Ranking-optimized CF wins overall. BPR and SAR — the two additions from the recommenders-team library — top every metric. Models trained to rank beat models trained to predict ratings by an order of magnitude at top-N, and on this sparse, weakly-sequential data they beat the 1B LLM too.

GenRec beats every rating-prediction baseline. 7–14× the personalized rating predictors at HR@5, with the right restaurant placed near the top when found — but it trails BPR and SAR, and at depth 10 also popularity: Yelp visits are weakly sequential, and GenRec's deduped beam lists average 8.9 names against the others' full 10.

Rating predictors are poor top-N retrievers. KNN and SVD predict ratings well (RMSE 0.93–0.99) yet almost never surface the next-visited restaurant. Optimizing squared error rewards obscure items with a few perfect ratings.

The LLM internalized the catalog. 97.7% of freely generated names are real businesses, and the hit/miss examples show it exploiting name semantics — yogurt shops for yogurt fans, sushi for sushi regulars — exactly the paper's motivation for names over IDs.

Consistent with the paper. GenRec reported HR@10 = 0.025 on sparse Amazon Toys — where it also lost to its baseline — versus 0.131 on dense MovieLens, where it won. This Yelp result sits squarely in the sparse-data pattern.

Caveats

  • Initial metrics: one training run, no hyperparameter search, 2 epochs, 30k of 98k possible training windows.
  • Name-level evaluation merges chain locations (every “Subway” counts as one item) — applied equally to all models.
  • Beam lists shorter than 10 handicap GenRec at the @10 metrics; raising beams to 15–20 is the first thing to try next.

Reproduce

Scripts in genrec/, run with the unsloth-studio Python

python genrec/01_prepare_data.py       # split + 30k training examples
python genrec/02_classic_baselines.py  # classic baselines + sanity check
python genrec/03_genrec_train.py       # ~21 min on RTX 5070 Ti
python genrec/04_genrec_infer.py       # ~4 min, 10-beam generation
python genrec/06_recommenders_baselines.py  # SAR + BPR (py3.11 venv, see README)
python genrec/05_evaluate.py           # final table
